# Приём

**Языки:** [English](../admission.md) | Русский

Приём — это путь, которым посторонний становится участником. Всё происходит в Telegram; игровой сервер
только применяет результат. В конвейере пять этапов: привязка, анкета, голосование, решение и членство в
группе.

## Этап 1 — Первый контакт и привязка

При первом входе игрок попадает в гостевой режим (полёт наблюдателя, ограниченные взаимодействия), а в
чат приходит личная deep-ссылка:

```text
To gain access to the server you need to
register through Telegram.

Telegram: t.me/ServerCoreBot?start=<one-time-code>
```

Ссылка несёт **одноразовый код привязки**, а не сырой Telegram ID и не UUID игрока в угадываемой форме.

После того как игрок открывает бота:

1. Backend проверяет одноразовый код.
2. Игрок подтверждает привязку Telegram в боте.
3. Backend убеждается, что UUID Minecraft действительно принадлежит этому человеку — сверяя с **живой
   сессией на сервере**, а не только с введённым ником.
4. Создаётся предварительная привязка Telegram ↔ UUID.
5. Анкета становится доступной.

Голый `/start` без валидного кода открывает интерфейс бота, но не создаёт аккаунт Minecraft.

## Этап 2 — Анкета

Анкета — пошаговый диалог в Telegram: один вопрос на сообщение, навигация inline-кнопками, отмена на
любом шаге, промежуточный прогресс сохраняется. Список вопросов приходит из конфигурации backend
(`APPLICATION_QUESTIONS_RU` / `APPLICATION_QUESTIONS_EN`, одинаковой длины), а каждый текст для
пользователя доступен на русском и английском — язык интерфейса каждый аккаунт выбирает через
`/language`.

Типичные вопросы:

1. Как давно вы играете в Minecraft?
2. Почему вы хотите присоединиться?
3. Как часто планируете играть?
4. Есть ли у вас опыт на похожих серверах?

Гарантии:

- Привязанный UUID подставляется автоматически — игрок не может приписать анкету не тому аккаунту.
- Повторные отправки ограничены по частоте; дубликат не может перезаписать ожидающую анкету.
- После отправки заявитель может перечитать анкету.
- **Одна заявка на UUID за 3 месяца.** Кулдаун привязан к `lastApplicationAt` и переживает удаление
  заявки — удаление старой анкеты не сбрасывает отсчёт.
- При отказе заявитель получает результат в боте.

## Этап 3 — Голосование

Отправка запускает голосование сообщества на **3 часа**. Голосование публикуется **в закрытой группе
Telegram**, а не в личных сообщениях: одна карточка, одна живая клавиатура. Голосующие — действующие
участники с активным аккаунтом; число голосующих **фиксируется в момент старта**, так что последующие
входы и выходы не могут сдвинуть планку, которую должно пройти идущее голосование.

Участники видят примерно такую карточку:

```text
NEW APPLICATION

Player: bejiihiu

Reason for joining:
...

Voting ends at 21:00 MSK.

[Accept (7)] [Reject (3)]
```

Голосовать могут только участники группы, у которых есть активный аккаунт ServerCore — бот проверяет
членство в группе (`chat_member`) и статус аккаунта в базе, прежде чем засчитать голос. Подтверждение
приходит голосующему **эфемерным ответом**, видимым только ему («голос учтён: ЗА, до кворума ещё N
голосов»), чтобы группа не тонула в болтовне по каждому голосу.

Правила целостности голосования:

- **Один UUID — один голос** на заявку; это обеспечивает уникальный составной индекс по (заявка,
  голосующий).
- Голосовать по собственной заявке нельзя.
- Голосовать без активного аккаунта нельзя.
- Голосовать, не находясь в группе, нельзя.
- Несколько Telegram-аккаунтов, привязанных к одному UUID, не умножают голоса.
- Повторные или устаревшие нажатия колбэков никогда не меняют уже записанный голос.
- Каждый голос сохраняется в MongoDB отдельной записью.

## Этап 4 — Решение

Два отдельных условия, нужны оба:

- **Кворум:** строго больше **50 %** имеющих право голоса (по составу, зафиксированному на старте)
  проголосовали. Ровно 50 % кворумом не считается.
- **Результат:** строго больше **50 %** действительных голосов — «за»; при равенстве заявка
  отклоняется.

Пример на числах: 20 имеющих право голоса, порог кворума — 11 (больше половины). Пришло двенадцать
голосов, 8 «за» и 4 «против». Кворум есть, и 8 > 50 % от 12 действительных голосов — заявка одобрена.

Если окно истекает без кворума, голосование **один раз автоматически продлевается ещё на 3 часа**. Если
и продление заканчивается без кворума, заявка помечается `EXPIRED` и уходит админам на ручное
рассмотрение — незавершённое голосование **никогда** не считается молчаливым одобрением. Результат
публикуется в сообщении голосования, заявитель получает уведомление в боте, а в админский чат уходит
копия решения.

## Этап 5 — Членство в группе

Одобрение — не финиш; членство подтверждается фактическим вступлением:

1. Заявка переходит в `APPROVED`.
2. Backend генерирует **одноразовую** ссылку-приглашение.
3. Заявитель получает ссылку в боте.
4. Когда игрок вступает в группу, бот получает событие о новом участнике.
5. Backend сопоставляет нового участника с одобренным аккаунтом и подтверждает связь.
6. Когда выполнены все условия активации, статус аккаунта становится `ACTIVE`.

Отправка приглашения сама по себе ничего не доказывает — доказывает подтверждённое вступление.

## После приёма

- **Повторная заявка:** после отказа или истечения UUID не может подать новую заявку 3 месяца.
- **Удаление аккаунта:** удаление отзывает доступ к Minecraft, отменяет ожидающие запросы авторизации,
  убирает участника из Telegram-группы через Bot API, отзывает неиспользованные приглашения и пишет
  обезличенную запись аудита.
- **Аудит:** фиксируется каждый переход этапа — отправка, старт голосования, каждый голос, решение,
  выдача приглашения, подтверждение в группе.
