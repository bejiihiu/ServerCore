# Конфигурация

**Языки:** [English](../configuration.md) | Русский

ServerCore настраивается в двух местах: в файле окружения backend и в `config.yml` плагина. Эта страница
описывает каждую опцию.

## Backend — переменные окружения

Все переменные берутся из `.env` (за основу скопируйте `.env.example`). Каждый ключ ниже читается и
проверяется Zod-конфигом backend при старте; невалидное значение прерывает запуск с описанием того, что
не так.

### Рантайм и хранилище

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `NODE_ENV` | нет | `development` | `development` / `production` / `test` |
| `PORT` | нет | `8080` | HTTP-порт; отдаёт эндпоинт `/health` (Fastify) |
| `HOST` | нет | `0.0.0.0` | Адрес привязки, общий для HTTP-сервера и WebSocket gateway |
| `WS_PORT` | нет | `8081` | Порт нативного WebSocket gateway — отдельный листенер, а не часть HTTP-сервера |
| `MONGODB_URI` | нет | `mongodb://localhost:27017/servercore` | Строка подключения MongoDB вместе с именем базы (`mongodb+srv://…` для Atlas) |
| `LOG_LEVEL` | нет | `info` | Уровень Pino: `trace`, `debug`, `info`, `warn`, `error`, `fatal` |
| `LOG_TIMEZONE` | нет | `Europe/Moscow` | Часовой пояс для отметок времени в логах и расписаний |

### Учётные данные серверов

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `SERVERCORE_SERVER_CREDENTIALS` | да | `{}` | JSON-объект «id сервера → HMAC-секрет сервера»: `{"game-1": "…"}`. Секреты должны быть не короче 32 символов (`openssl rand -hex 32`). Конфиг плагина каждого игрового сервера несёт совпадающие id и секрет |
| `SERVER_NAME` | нет | `ServerCore` | Красивое имя сервера, показываемое в запросах авторизации в Telegram |

|---|---|---|---|
| `RETENTION_AUDIT_DAYS` | нет | `90` | Время жизни записей аудита и событий сервера |

## Плагин — config.yml

Лежит в `plugins/ServerCore/config.yml`, создаётся при первом старте. Поставляемый файл намеренно неполон
в двух ключах: `backend.url` и `backend.secret` пустые, и плагин отказывается включаться, пока оба не
заполнены. Загрузка с нерабочим блоком `backend` пишет `config error: …` и выключает плагин вместо
работы в полуподключённом состоянии. Когда плагин включён, недоступный backend деградирует мягко: новые
входы отказывают по умолчанию, а гости продолжают работать по локальному состоянию.

### backend

| Ключ | По умолчанию | Описание |
|---|---|---|
| `backend.url` | — (обязателен) | Полный WebSocket URL gateway backend, `wss://host:port/path` (`ws://` для локальной разработки; TLS терминируется на прокси). Должен начинаться с `ws://` или `wss://` |
| `backend.server-id` | `game-1` | Уникальный id этого игрового сервера; должен совпадать с ключом в `SERVERCORE_SERVER_CREDENTIALS` на backend. Допустимые символы: `a-z 0-9 . _ -` |
| `backend.secret` | — (обязателен) | HMAC-секрет этого сервера, соответствующий тому же ключу на backend. Не короче 32 символов (`openssl rand -hex 32`) |
| `backend.reconnect.initial-delay-seconds` | `2` | Первая задержка переподключения после разрыва |
| `backend.reconnect.max-delay-seconds` | `120` | Потолок экспоненциального backoff |
| `backend.heartbeat-interval-seconds` | `15` | Интервал между heartbeat-кадрами; должен быть положительным |
| `backend.ack-timeout-milliseconds` | `10000` | Сколько ждёт неподтверждённый кадр перед первой повторной попыткой |
| `backend.ack-max-retries` | `2` | Повторы после первого таймаута ack; durable-кадры затем откладываются на диск до возврата связи, остальные отбрасываются |
| `backend.liveness-timeout-milliseconds` | `45000` | Если на «подключённом» сокете столько времени нет входящих кадров — связь полуоткрыта, нужно принудительное переподключение |
| `backend.dedupe-ttl-milliseconds` | `600000` | Сколько помнится обработанный push от backend; повторно доставленная копия внутри окна подтверждается, но никогда не применяется дважды |
| `backend.outbox-max-entries` | `500` | Жёсткий лимит файла durable-очереди (кадры жизненного цикла гостя) |

Конфиги, записанные до появления вложенной секции `backend.reconnect.*`, могут всё ещё содержать плоские
ключи `backend.reconnect-initial-seconds` и `backend.reconnect-max-seconds`. Они по-прежнему принимаются
как запасной вариант, когда вложенных ключей нет; новым установкам стоит использовать вложенную форму.

### guest

| Ключ | По умолчанию | Описание |
|---|---|---|
| `guest.enabled` | `true` | Главный переключатель. Когда выключен, неавторизованные игроки получают кик с сообщением о регистрации вместо входа в гостевой режим |
| `guest.restore-on-restart` | `true` | Пересоздавать гостевые сессии и восстанавливать снапшоты после перезапуска сервера |
| `guest.resolve-timeout-milliseconds` | `4000` | Сколько может длиться проверка аккаунта через backend, прежде чем плагин откатится на локальное состояние (отказ по умолчанию → гость) |
| `guest.session-limit` | `3` | Максимум гостевых сессий на игрока. Каждый вход без авторизации сжигает одну; успешная авторизация сбрасывает лимит |
| `guest.kick-after-limit` | `true` | После лимита: `true` — кик с экраном «зарегистрируйся сейчас», `false` — игрок продолжает исследовать мир с заметным предупреждением |
| `guest.reminder-interval-seconds` | `60` | Частота ненавязчивого напоминания в actionbar, пока гость ждёт авторизации |
| `guest.gamemode-sweep-seconds` | `2` | Как часто свип перепроверяет, что гость всё ещё в Spectator (другой плагин может принудительно сменить режим); правки троттлятся, чтобы это не превратилось в борьбу каждый тик |
| `guest.lang` | `ru` | Язык интерфейса, выбирает `locales/<lang>.yml` из канонического хранилища (`en` и `ru` поставляются в комплекте) |
| `guest.bot-username` | `ServerCoreBot` | Username Telegram-бота, используется для запасной deep-ссылки, когда личная одноразовая ссылка ещё не выдана |
| `guest.link-ttl-milliseconds` | `90000` | Личные deep-ссылки несут одноразовые токены; после этого окна они перестают показываться |
| `guest.snapshot-storage-path` | `guest-snapshots.json` | Файл durable-хранилища снапшотов, относительно `plugins/ServerCore/` |
| `guest.command-whitelist` | `help, rules, link` | Имена команд (без слэша), которые гость всё ещё может выполнять. На `/link` плагин сам отвечает запросом регистрации |
| `guest.local-accounts` | — | Необязательные переопределения `uuid: authorized` или `uuid: banned`, действующие, пока backend недоступен. На этом offline-mode сервере UUID — лишь производная от ника, так что это удобная бухгалтерия; источником истины по личности остаётся привязка в Telegram на backend |

### guest.restrictions

Переключатели взаимодействий для гостя. У каждого значение по умолчанию `true` (запрещено):

`guest.restrictions.block-interaction`, `block-break`, `block-place`, `item-pickup`, `item-use`, `container-interaction`, `entity-damage`, `commands`, `gamemode-change`, `portals`, `inventory-edit`, `chat`

`chat` — полная изоляция: гость не видит и не пишет в чат, а подавление срабатывает раньше, чем другие
чат-плагины увидят событие. Гостям гарантированы только свободный полёт и наблюдение за миром; всё
перечисленное выше запрещено по замыслу.

### Сообщения гостя

Тексты для игроков живут в одном каноническом хранилище: `locales/ru.yml` и `locales/en.yml`. Оба файла
поставляются внутри jar плагина и имеют одинаковый набор вложенных ключей — `tablist.*`, `guest.*`,
`auth.*`, `account.*`, `spec.*`, `protection.*`, `luckperms.groups.*`, блок `placeholders.*`, который
питает расширение PlaceholderAPI, и `countdown.*`. `guest.lang` выбирает активный язык; ключ, которого в
нём нет, берётся из английского файла, а ключ, отсутствующий везде, отображается как сам ключ.

Backend присылает канонический бандл `ru` целым файлом по WebSocket (`LOCALE_PUSH`); плагин сохраняет его
в `plugins/ServerCore/locales/ru.yml`, и эта сохранённая копия при старте важнее той, что лежит в jar. Тот
же канал принимает `en`, но backend сейчас отдаёт только `ru` — английский файл едет в jar плагина как
базовый слой.

Шаблоны — это MiniMessage только с тегами темы плагина (`<primary>`, `<secondary>`, `<muted>`, `<gold>`,
`<ok>`, `<warn>`, `<danger>`, `<info>`); ванильные названия цветов отклоняются сборкой, чтобы палитра
оставалась в одном месте. Значения приходят как плейсхолдеры `{name}` и экранируются перед подстановкой.
Исключение — `placeholders.*`: эти значения представляют собой обычный legacy-текст для PlaceholderAPI и
не несут тегов.

### anti-esp

| Ключ | По умолчанию | Описание |
|---|---|---|

| `anti-esp.sneak-hides` | `true` | Игроки, которые сейчас приседают, для наблюдателей без прямой видимости определяются как `HIDDEN` |
| `anti-esp.disguise.enabled` | `true` | Заменять скрытых игроков синтетической сущностью для конкретного наблюдателя, а не убирать их совсем |

### spec (скрытое наблюдение)

| Ключ | По умолчанию | Описание |
|---|---|---|
| `spec.enabled` | `true` | Главный переключатель `/spec` |
| `spec.live-inventory` | `true` | Просмотр инвентаря в реальном времени только для чтения во время наблюдения |
| `spec.live-inventory-push-milliseconds` | `500` | Минимальный разрыв между обновлениями живого просмотра инвентаря |
| `spec.live-inventory-full-resync-seconds` | `5` | Периодическая полная пересинхронизация живого просмотра; ловит изменения, о которых не сообщило ни одно событие (например, правки инвентаря на стороне плагина) |
| `spec.log-to-audit` | `true` | Каждый старт и конец сессии пишется в `audit_logs` (backend) и в локальную цепочку аудита |
| `spec.permission.use-luckperms` | `true` | LuckPerms служит источником прав, когда установлен; иначе ванильные проверки |
| `spec.permission.levels` | `[owner, admin, moderator, helper]` | Уровни доступа, от высшего к низшему: членство в перечисленной группе даёт этот уровень |
| `spec.permission.spec-permission` | `servercore.spec` | Отдельный узел, который тоже даёт доступ |
| `spec.permission.fallback-level` | `helper` | Уровень, выдаваемый одним `spec-permission`, когда ни одна из перечисленных групп не совпала |
| `spec.audit.directory` | `audit` | Локальная цепочка аудита только на дозапись (jsonl), относительно `plugins/ServerCore/`; файлы ротируются ежедневно как `spec-audit-YYYY-MM-DD.jsonl` |
| `spec.audit.retention-days` | `30` | Ротированные файлы старше этого срока удаляются |
| `spec.audit.max-entries-per-session` | `64` | Сколько строк аудита разрешено на одну сессию, переполнение отбрасывается |
| `spec.audit.queue-capacity` | `1024` | Ограниченный буфер записи; полный буфер отбрасывает записи, а не блокирует |
| `spec.hidden.trace-radius` | `1.5` | Как пакет следа (частица/звук, направленный на наблюдаемого игрока) привязывается к смотрящему админу по близости. Держите маленьким — больший радиус начинает съедать собственные эффекты цели |
| `spec.hidden.suppress-action-bar` | `true` | Отбрасывать каждую строку actionbar, адресованную наблюдаемому игроку, во время сессии. Пакеты actionbar не несут источника, поэтому это работает по принципу «всё или ничего» на сессию |

### protection

| Ключ | По умолчанию | Описание |
|---|---|---|
| `protection.enabled` | `true` | Главный переключатель всего стека: запрет команд, защита геймода, аудит командных блоков |
| `protection.blocked-commands` | встроенный список | Имена команд, которые игроки не могут выполнять никогда, с OP или без. Список поставляется с полным базовым набором в `config.yml`; если ключ удалить целиком, применяется встроенный базовый набор, а явно пустой список отключает блокировку. Алиасы разрешаются по живому дереву команд (одно имя покрывает всю группу алиасов), префиксы пространства имён при сопоставлении игнорируются |
| `protection.blocked-datapack-commands` | `function, schedule, datapack` | Команды, передающие выполнение коду датапака — функция может нести внутри любую заблокированную команду, поэтому пути её вызова тоже запрещены игрокам |
| `protection.enforce-gamemode` | `true` | Не-survival геймоды разрешены только через санкционированные потоки ServerCore (гостевые сессии, `/spec`, реестр переопределений); всё остальное отменяется, а уехавшие режимы возвращаются периодическим свипом |
| `protection.gamemode-sweep-interval-seconds` | `30` | Как часто работает свип дрейфа режимов; `0` = выключено |
| `protection.command-block-audit-interval-seconds` | `600` | Как часто загруженные чанки сканируются на командные блоки с запрещённой командой (события выполнения для блоков не существует); `0` = аудит выключен. События загрузки чанков аудируются всегда |
| `protection.command-block-neutralize` | `false` | Очищать запрещённую команду в самом блоке, а не только логировать |
| `protection.hide-from-tab-complete` | `true` | Убирать запрещённые команды из списка команд клиента (автодополнение по Tab) — только отображение, принуждение происходит во время выполнения |

### luckperms.fallback

Права живут в LuckPerms (soft-depend). Когда LuckPerms установлен на сервере, всё в этой секции
игнорируется — группы и узлы управляются через сам LuckPerms. Секция читается только без LuckPerms:
статичная замена из конфига, чтобы плагин всё равно запускался и у админов оставался доступ. Это никогда
не замена настоящему управлению группами.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `luckperms.fallback.default-group` | `default` | Группа, выдаваемая каждому игроку, о котором статическая карта ничего не знает |
| `luckperms.fallback.groups` | — | Статические переопределения групп, `uuid: имя группы` (только порядок рангов) |
| `luckperms.fallback.permissions.everyone` | `[]` | Узлы, выдаваемые каждому игроку |
| `luckperms.fallback.permissions.players` | — | Узлы на игрока: точные узлы или префиксные wildcard'ы (`servercore.*`) |

### flectonepulse

FlectonePulse — источник модерации и чата на этом сервере; ServerCore никогда не выдаёт баны, муты,
варны и кики, не форматирует чат и не поставляет префиксы — он только читает публичный API
FlectonePulse и сверяется с состоянием наказаний, когда для решения это нужно. Чтобы всё это работало,
FlectonePulse должен быть установлен.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `flectonepulse.disable-tg` | `true` | Дедупликация: у FlectonePulse есть собственный Telegram-модуль, и когда он активен, события объявляет именно он — тогда ServerCore держит свои ops-уведомления вне Telegram, чтобы ничего не объявлялось дважды. `false` = ServerCore объявляет в любом случае |
| `flectonepulse.punishment-cache-ttl-seconds` | `30` | Сколько кешируется ответ проверки наказания; досрочно сбрасывается событиями игроков FlectonePulse, так что это лишь страховка |

### Валидация и приведение значений

Конфиг валидируется один раз при загрузке. Перечисленные проблемы прерывают загрузку строкой
`config error: <what>` в логе и выключают плагин (исправьте значение, перезапустите):

- `backend.url` пуст или не `ws://` / `wss://`; `backend.server-id` вне `a-z 0-9 . _ -`; `backend.secret` короче 32 символов
- `backend.heartbeat-interval-seconds`, `ack-timeout-milliseconds`, `liveness-timeout-milliseconds`, `dedupe-ttl-milliseconds`, `outbox-max-entries` не положительные; `ack-max-retries` отрицательный
- `spec.live-inventory-push-milliseconds` вне `50–10000`; `spec.live-inventory-full-resync-seconds` меньше интервала push
- `spec.audit.directory` пуст или содержит `..`

Всё остальное деградирует, а не ломает загрузку:

- **Приводится** к безопасному диапазону: `anti-esp.max-distance` `8–128`, `check-interval-ticks` `1–200`, `cache.ttl-ticks` `1–2000`, `spec.hidden.trace-radius` `0.5–16`, `guest.resolve-timeout-milliseconds` `250–30000`, `session-limit` `1–100`, `reminder-interval-seconds` `10–3600`, `gamemode-sweep-seconds` `1–60`, `link-ttl-milliseconds` `5000–600000`, аудиторные `retention-days`/`max-entries-per-session`/`queue-capacity` (ниже 1 / 1 / 16), `flectonepulse.punishment-cache-ttl-seconds` `1–3600`, `ops.restart.grace-seconds` `0–600`, `ops.update.check-interval-minutes` не меньше `1`
- **Отбрасывается со строкой в логе**: неизвестные имена в `anti-esp.disguise.mobs`, некорректные записи `ops.restart.daily-times`, не-UUID ключи в `guest.local-accounts` / `luckperms.fallback.groups` / `luckperms.fallback.permissions.players`, пустые имена групп
- **Откатывается**: неизвестный `ops.restart.timezone` становится `Europe/Moscow`; `spec.permission.fallback-level` не из `spec.permission.levels` становится самым низким из перечисленных; пустой `guest.command-whitelist` становится `help, rules, link`; отсутствующий `ops.restart.daily-times` становится `["05:00"]` (явный `[]` по-прежнему означает «без плановых рестартов»)
- **Игнорируется без побочных эффектов**: любая опциональная секция плагина (`luckperms`, `placeholders`, `flectonepulse`) может отсутствовать целиком; `anti-esp.enabled: false` останавливает и движок видимости, и пакетный слой, а `spec.enabled: false` просто пропускает стек `/spec`. Плагин всё равно загружается.

## Команды плагина

| Команда | Доступ | Описание |
|---|---|---|
| `/spec` | политика `spec.permission.*` (группы LuckPerms или отдельный узел) | Выйти из текущей сессии наблюдения |
| `/spec <player>` | та же | Начать скрытую сессию наблюдения за игроком; автодополнение по Tab предлагает имена онлайн-игроков |
| `/servercore groups <player>` | `servercore.admin` (консоль всегда разрешена) | Отладочный вывод со списком групп игрока из активного источника прав |
| `/servercore deop-all` | `servercore.admin` (консоль всегда разрешена) | Снять статус оператора со всех аккаунтов, у которых он есть |
| `/link` | гости | Это не зарегистрированная команда — гость, набравший `/link`, получает в чате запрос регистрации вместо «unknown command» |

Набор команд Telegram-бота отдельный и целиком живёт в backend: `/start`, `/status`, `/application`,
`/myapplication`, `/cancel`, `/language`, `/help`, плюс админский `/stats` (доступен только
`ADMIN_TELEGRAM_IDS`).

## Принципы конфигурации

- **Отказ по умолчанию (fail closed).** Если backend недоступен, новые входы отклоняются — никогда не
  одобряются автоматически.
- **Секреты не попадают в репозиторий.** `backend.secret` и все токены существуют только на хостах, где
  они нужны.
- **Наименьшие привилегии.** Права плагина повторяют группы LuckPerms; ничего не выдаётся «на всякий
  случай».
- **Переживает рестарты.** Гостевые снапшоты плагин хранит локально (и зеркалит в backend), а состояние
  сессий живёт в MongoDB — и то и другое переживает рестарты и падения backend.
