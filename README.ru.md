# ServerCore

🇬🇧 [English](README.md)

> Инфраструктура закрытого survival-сервера: приём участников через Telegram, вход без пароля и
> укреплённый рантайм на Folia.

**Статус проекта:** API нестабилен, семантического версионирования нет. Каждая сборка обозначается как
`build-<commitCount>-<shortSha>`, и этот тег является именем релиза. Если на странице Releases ещё нет
отмеченной сборки, запустите backend из исходников и соберите плагин локально — шаги ниже работают в
любом случае. История изменений — в [CHANGELOG.md](CHANGELOG.md), короткий чеклист оператора — в
[docs/ru/first-run.md](docs/ru/first-run.md).

## Что это

ServerCore — инфраструктура закрытого survival-сервера Minecraft. Сам геймплей она не трогает: игроки,
которые уже внутри, видят обычный survival-сервер, а всё остальное (приём, идентичность, контроль
доступа, защита) уходит в автоматизированный слой, который живёт в основном в Telegram.

- **Telegram — это интерфейс управления.** Регистрация, заявки, голосования, подтверждения входа и
  управление аккаунтом происходят через бота, а не через игровые команды.
- **Приём решает сообщество.** Новые игроки заполняют заявку в Telegram, действующие участники
  голосуют, и кворум выносит решение.
- **Входа по паролю нет.** Каждая сессия подтверждается одним нажатием в Telegram. Никаких паролей,
  никакого `/login`.
- **Посторонние всё равно могут осмотреться.** Незарегистрированные игроки попадают в ограниченный
  гостевой режим с полётом наблюдателя, причём их исходная позиция сохраняется в снапшот и потом
  восстанавливается.
- **Читерские клиенты получают меньше.** Слой anti-ESP управляет тем, что каждый отдельный клиент
  видит о каждом другом игроке, вплоть до маскировок и синтетических атрибутов для конкретного
  наблюдателя.
- **Админы могут смотреть, оставаясь незамеченными.** Скрытая команда наблюдения позволяет персоналу
  невидимо следовать за игроком с живым просмотром инвентаря только для чтения; всё пишется в аудит.
- **Сервер закрыт на замок.** Опасные команды заблокированы для всех, OP не используется для
  повседневного администрирования, а смены геймода вне санкционированных сценариев откатываются.
- **Обслуживание сервера встроено.** Плагин сам обновляется из релизов GitHub, планирует ежедневные
  рестарты (по желанию — через панель Pterodactyl) и отправляет своё живое состояние — игроков, TPS,
  активные сессии наблюдения — в backend и в `/stats` бота.

Это намеренно *не* универсальный «everything-core»-плагин. Модерация и чат остаются за
[FlectonePulse](https://github.com/FlectonePulse/FlectonePulse), права — за [LuckPerms](https://luckperms.net/),
а ServerCore делает остальное, не дублируя ни то ни другое.

## Обзор архитектуры

Два независимых приложения — backend на Bun/TypeScript с Telegram-ботом и Kotlin-плагин внутри сервера
Folia — общаются друг с другом через единственный защищённый WebSocket-канал.

```text
                 TELEGRAM
                    |
                grammY bot
                    |
             Bun backend
                    |
          application services
                    |
                 Mongoose
                    |
                 MongoDB
                    |
                 WebSocket  (the only plugin <-> backend link)
                    |
             Minecraft plugin
                    |
          +---------+---------+
          |                   |
       Folia API         PacketEvents
          |                   |
          +---------+---------+
                    |
                 Minecraft
                    |
              FlectonePulse
```

## Компоненты

| Компонент | Стек | Ответственность |
|---|---|---|
| Backend | Bun, TypeScript, Fastify, grammY, Zod, Pino | Telegram-бот, приём, голосования, жизненный цикл аккаунтов, токены авторизации, уведомления, хранение данных |
| Плагин | Kotlin, Java 25, PacketEvents | Гостевой режим, принудительная авторизация, anti-ESP, скрытое наблюдение, защита команд, учёт сессий, самообновление и рестарты |
| База данных | MongoDB + Mongoose | Все постоянные данные: аккаунты, заявки, голоса, сессии, снапшоты, аудит-логи |
| Транспорт | WebSocket (WSS) | Единственный канал между backend и плагином, подписанный и защищённый от повторов |
| Интеграции | FlectonePulse, LuckPerms, PlaceholderAPI | Чат и модерация, права, публичные плейсхолдеры статуса |

## Требования

- **Java 25** (рантайм и сборка плагина)
- **Folia 26.3 или новее** — Paper не поддерживается
- **Bun** как рантайм backend (Node.js не используется)
- **MongoDB** 7.x или новее
- **Токен Telegram-бота** от [@BotFather](https://t.me/BotFather)
- **Закрытая группа Telegram**, которой бот может управлять

## Установка

Установка выполняется только из релизов — не собирайте из исходников, если не планируете разрабатывать
проект.

1. **Скачайте jar плагина** — `ServerCore-<tag>.jar` со страницы [GitHub Releases](https://github.com/bejiihiu/ServerCore/releases) — и положите его в папку `plugins/` вашего сервера Folia. Сверьте файл с `SHA256SUMS.txt` из релиза.
2. **Скачайте backend** — готовый бандл `servercore-backend-<tag>.tar.gz` либо исходники, если хотите запускать его напрямую через Bun.
3. **Настройте окружение backend** — скопируйте пример файла окружения рядом с backend и заполните значения. Каждая переменная описана в [docs/ru/configuration.md](docs/ru/configuration.md).
4. **Поднимите MongoDB.** Разверните standalone-инстанс или replica set, создайте базу для ServerCore и положите строку подключения в окружение backend. Рекомендуемые индексы создаются автоматически при первом старте.
5. **Создайте Telegram-бота** через [@BotFather](https://t.me/BotFather): `/newbot`, сохраните токен и отключите privacy mode (`/setprivacy` → Disable), чтобы бот мог подтверждать вступление в группу.
6. **Подготовьте сервер Folia.** Установите [PacketEvents](https://packetevents.com/) (обязательно — на нём держится пакетный слой), а также [FlectonePulse](https://github.com/FlectonePulse/FlectonePulse) и [LuckPerms](https://luckperms.net/), если нужен полный набор функций. Убедитесь, что ни один игровой аккаунт не имеет OP, и запустите сервер один раз, чтобы плагин создал свою конфигурацию.
7. **Разместите конфигурацию плагина.** Отредактируйте `plugins/ServerCore/config.yml` на сервере — там живут URL backend, секрет сервера, гостевой режим и настройки anti-ESP. Все ключи описаны в [docs/ru/configuration.md](docs/ru/configuration.md).

Подробное пошаговое руководство с реальными примерами конфигурации — в [docs/ru/installation.md](docs/ru/installation.md).
